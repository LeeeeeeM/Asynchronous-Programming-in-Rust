# Rust 异步执行器 - 协程与 Pin 实现

这是一个基于 Rust 的异步执行器实现，展示了如何使用 Pin 和协程状态机来实现异步编程。

## 项目结构

```
src/
├── main.rs          # 主程序入口，包含协程状态机实现
├── future.rs        # Future trait 定义
├── http.rs          # HTTP 异步请求实现
├── runtime.rs       # 运行时模块入口
└── runtime/
    ├── executor.rs  # 执行器核心实现
    └── reactor.rs   # 事件循环实现
```

## 关键数据结构

### 核心类型定义

```rust
// 任务类型：所有 Future 的统一包装
type Task = Pin<Box<dyn Future<Output = String>>>;

// Future trait 定义
pub trait Future {
    type Output;
    fn poll(self: Pin<&mut Self>, waker: &Waker) -> PollState<Self::Output>;
}

// 轮询状态
pub enum PollState<T> {
    Ready(T),
    NotReady,
}
```

### 执行器核心

```rust
// 执行器核心数据结构
struct ExecutorCore {
    tasks: RefCell<HashMap<usize, Task>>,        // 任务存储
    ready_queue: Arc<Mutex<Vec<usize>>>,         // 就绪队列
    next_id: Cell<usize>,                        // 下一个任务ID
}

// 执行器主结构
pub struct Executor;

// Waker 实现
#[derive(Clone)]
pub struct Waker {
    thread: Thread,                              // 当前线程
    id: usize,                                   // 任务ID
    ready_queue: Arc<Mutex<Vec<usize>>>,         // 就绪队列引用
}
```

### 协程状态机

```rust
// 协程状态枚举
enum State0 {
    Start,                                       // 初始状态
    Wait1(Pin<Box<dyn Future<Output = String>>>), // 等待第一个HTTP请求
    Wait2(Pin<Box<dyn Future<Output = String>>>), // 等待第二个HTTP请求
    Resolved,                                    // 完成状态
}

// 栈数据结构
#[derive(Default)]
struct Stack0 {
    buffer: Option<String>,                      // 缓冲区
    writer: Option<*mut String>,                 // 写入器指针
}

// 协程结构体
struct Coroutine0 {
    stack: Stack0,                               // 栈数据
    state: State0,                               // 当前状态
    _pin: PhantomPinned,                         // Pin 标记
}
```

### HTTP 异步实现

struct HttpGetFuture {

## 核心特性

### 1. Pin 安全保证
- 使用 `Pin<Box<F>>` 确保 Future 不会被移动
- `PhantomPinned` 标记自引用结构体
- 通过 `unsafe { self.get_unchecked_mut() }` 安全获取可变引用

### 2. 状态机协程
- 将异步函数转换为状态机
- 每个 `.await` 点对应一个状态
- 栈数据通过指针保存，避免移动问题

### 3. 执行器优化
- 预检查 Future 是否已准备好
- 避免不必要的执行器循环开销
- 使用线程本地存储管理任务

### 4. Waker 机制
- 每个任务都有唯一的 Waker
- 异步操作完成时自动唤醒执行器
- 支持跨线程通知
